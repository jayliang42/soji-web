# Quick Task Plan

## Goal

Turn the Support page checklist into an actionable request composer that helps
customers send one useful, structured message without requiring an account or
storing their issue details. Prefill a configured email channel and preserve a
clear copy fallback for web-based or unavailable support channels.

## Tasks

1. Build deterministic support-request formatting and mailto generation for a
   small set of issue categories, required issue details, and optional context.
2. Replace the static contact checklist with an accessible, responsive form
   that previews the prepared request, opens a prefilled email when available,
   and copies or exposes the text manually when browser clipboard APIs fail.
3. Verify formatting, validation, email and copy paths, keyboard/touch use,
   320px layout, accessibility, existing self-service routing, and production
   build behavior.

## Reference

- USWDS recommends simple vertical form layouts, native fieldset/legend
  semantics for related choices, and contextual error messages beside inputs.
- GOV.UK recommends specific textarea hints and direct validation messages, and
  warns against requesting personal or financial data users do not need to
  provide.
- Zendesk supports issue-specific ticket fields and prefilled subjects and
  descriptions to reduce end-user effort while giving support teams consistent
  context.
